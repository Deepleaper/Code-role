# Real Project Cases / 真实项目案例

These cases explain why Code-role exists through real project decisions rather than hypothetical role diagrams.

这些案例不再用抽象角色图解释 Code-role，而是用真实项目决策说明它为什么存在。

## Cases

- [DeepBrain: strong evidence is not milestone completion](deepbrain.md)
- [Leaper Agent: an evaluation plan is not an executable baseline](leaper-agent.md)

## Disclosure Boundary / 公开边界

Both source repositories are private. The maintainer explicitly authorized these projects to be used as Code-role cases. The public case studies therefore:

- use project names and aggregate milestone evidence;
- omit source code, private repository links, local paths, customer data, task contents, credentials, and internal implementation details;
- distinguish project-internal independent evaluation from a public third-party audit;
- record a dated workflow snapshot rather than a permanent capability claim;
- preserve every rejected claim and every `0` gate from the source decision records.

两个源项目都是私有仓库，维护者已明确授权将其作为 Code-role 案例。公开内容仅保留项目名称、聚合指标和里程碑决策，不公开源码、私有仓库地址、本地路径、客户数据、任务正文、凭据或内部实现细节。

## How To Read The Cases / 如何理解这些案例

A Code-role case is successful when it makes the correct milestone decision. That decision may be:

- accept independently proven evidence;
- reject a role return;
- keep a KR at `0`;
- prevent Engineering from starting against an invalid baseline;
- reject production, benchmark, or superiority claims;
- route one precise gap back to the correct workstation.

“流程成功”不等于“里程碑必须通过”。如果证据不完整，正确地保持 `0`、打回角色、阻止错误开工，同样是 Code-role 的核心价值。
