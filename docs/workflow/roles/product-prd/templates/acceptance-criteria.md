# Acceptance Criteria / 验收标准

Each committed requirement must have at least one verifiable acceptance criterion.

每个 committed requirement 必须至少有一个可验证的验收标准。

| ID | Linked Requirement / 关联需求 | User Outcome / 用户结果 | Observable Behavior / 可观察行为 | Verification Method / 验证方法 | Evidence Source / 依据来源 | Priority | Non-Regression Boundary / 不破坏边界 |

## Invalid Criteria / 无效验收标准

Do not use vague criteria such as "feature works", "documentation is complete", or "UX is better" without observable behavior and verification method.

不要使用“功能可用”“文档完整”“体验更好”这类没有可观察行为和验证方法的标准。
